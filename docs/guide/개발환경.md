## 1. 전체 구조 먼저 보기

개발할 때는 프로그램 **세 개**가 동시에 떠 있어요.

```
                      브라우저 http://localhost:5173
                                 │
                                 ▼
┌──────────────────────────────────────────────┐
│ ① Vite 개발 서버 (frontend, :5173)            │  React 화면. 코드를 저장하면 바로 새로고침
│    /api/*, /uploads/* 요청은 8080으로 전달    │
└──────────────────────┬───────────────────────┘
                       ▼
┌──────────────────────────────────────────────┐
│ ② Spring Boot (backend, :8080)                │  REST API, 업로드 파일 제공
└──────────────────────┬───────────────────────┘
                       ▼
┌──────────────────────────────────────────────┐
│ ③ PostgreSQL 17 (Docker 컨테이너, :5432)      │  ownlog-postgres
└──────────────────────────────────────────────┘
```

운영(배포)에서는 ①이 없어요. React를 미리 빌드해서 ② Spring Boot가 화면 파일까지 함께 돌려줘요 (`Dockerfile`).

   - `.env`는 `application.yaml`이 `./.env`와 `../.env` 두 곳에서 찾아요. 실행 위치가 루트든 `backend`든 동작해요.
5. 테스트: 테스트 클래스 옆 ▶. **Docker가 켜져 있어야** 해요(10장).

- `frontend` 폴더를 열어 써도 돼요. `.vscode/`, `.idea/`는 `.gitignore`에 있어서 개인 설정이 커밋되지 않아요.
- 린트는 **oxlint**(`npm run lint`)를 써요. ESLint 설정 파일은 없어요.

## 5. 환경 변수와 `.env`

### 개념
**환경 변수**는 프로그램 밖에서 넣어 주는 설정값이에요. 비밀번호 같은 값을 **코드에 적지 않고** 실행할 때 넣기 위해 써요. 코드는 GitHub에 공개되지만 환경 변수는 내 컴퓨터(또는 서버)에만 있어요.

`.env`는 환경 변수를 모아 둔 파일이에요. **`.gitignore`에 들어 있어서 커밋되지 않아요.** 대신 어떤 값이 필요한지 알려 주는 `.env.example`(가짜 값)을 커밋해 둬요.

### 로컬 `.env` (`.env.example`을 복사)
| 키 | 예시 값 | 쓰는 곳 | 설명 |
|---|---|---|---|
| `DB_NAME` | `ownlog` | docker-compose, Spring | DB 이름 |
| `DB_USERNAME` | `ownlog` | docker-compose, Spring | DB 사용자 |
| `DB_PASSWORD` | `change-me` → **바꿔요** | docker-compose, Spring | DB 비밀번호. 없으면 `docker compose`가 "`.env 파일에 DB_PASSWORD를 설정해 주세요`"라며 멈춰요 |
| `JWT_SECRET` | `change-me-...` → **바꿔요** | Spring (`ownlog.jwt.secret`) | 로그인 토큰 서명 비밀키. **32바이트 이상.** `openssl rand -base64 48`로 만들어요 |

`.env.example`에는 없지만 `application.yaml`에 기본값이 있어서 **필요할 때만** 넣는 키
| 키 | 기본값 | 설명 |
|---|---|---|
| `DB_HOST` | `localhost` | DB 주소 |
| `DB_PORT` | `5432` | DB 포트 |
| `UPLOAD_DIR` | `./uploads` | 업로드 파일 저장 폴더 ([파일 업로드 가이드](파일-업로드.md)) |

### 운영 서버의 환경 변수 (참고)
운영에서는 `.env`를 쓰지 않아요. GitHub **Repository secrets** → `deploy.yml` → `deploy.sh` → `docker run -e`로 전달돼요.
| 키 | 설명 |
|---|---|
| `DB_ADDRESS`, `DB_PORT`, `DB_NAME`, `DB_USERNAME`, `DB_PASSWORD`, `DB_SCHEMA` | 수업 DB 접속 정보 (운영은 `DB_HOST`가 아니라 `DB_ADDRESS`예요) |
| `JWT_SECRET` | 없으면 서버에서 한 번 만들어 `~/ownlog-deploy/jwt.secret`에 두고 계속 써요 |
| `SERVER_PORT` | `8360` (`deploy.yml`의 `APP_PORT`) |
| `SPRING_PROFILES_ACTIVE` | `prod` (Dockerfile의 `ENV`) |

### 비밀값 규칙
- `.env`, 비밀번호, JWT 비밀키를 **코드·커밋·채팅에 쓰지 않아요.**
- 실수로 커밋해 푸시했다면 그 값을 **바꿔야** 해요 (이력에 남아 있어요).
- `JWT_SECRET`을 바꾸면 기존 로그인 토큰이 모두 무효가 돼서 **모두 로그아웃**돼요.

## 6. Spring 프로필: 기본 · prod · test

**프로필**은 "상황별 설정 묶음"이에요. 같은 코드를 로컬·운영·테스트에서 다른 설정으로 실행하게 해 줘요. 기본 설정(`application.yaml`) 위에 프로필 파일이 **덮어써요.**

| 프로필 | 켜지는 때 | 파일 | 무엇이 달라요? |
|---|---|---|---|
| (기본) | 로컬에서 `./gradlew bootRun` | `application.yaml` | `.env` 읽기, `localhost:5432`, 업로드 `./uploads`, 파일 5MB 제한, JWT 2시간, `ddl-auto: validate` |
| `prod` | Docker 이미지 (`SPRING_PROFILES_ACTIVE=prod`) | `application-prod.yaml` | DB 주소에 `currentSchema=${DB_SCHEMA}`, Flyway도 그 스키마에, Nginx 뒤라서 `forward-headers-strategy: framework`, 업로드 `/app/uploads` |
| `test` | 테스트 클래스의 `@ActiveProfiles("test")` | `src/test/resources/application-test.yaml` | 고정 JWT 비밀키(`.env` 없이 CI에서도 동작), 업로드 `build/test-uploads`, SQL 개수를 세는 Hibernate 통계 |

테스트의 DB는 설정 파일이 아니라 `TestcontainersConfiguration`이 정해요. `@ServiceConnection`이 테스트용 `postgres:17` 컨테이너를 띄우고 접속 정보를 자동으로 넣어 줘요. 그래서 로컬 DB(`ownlog-postgres`)와 **완전히 별개**이고, 테스트가 로컬 데이터를 건드리지 않아요.

`ddl-auto: validate`의 뜻: JPA가 테이블을 **만들지 않고**, 엔티티와 테이블이 맞는지 **검사만** 해요. 테이블은 Flyway(`db/migration/V*.sql`)가 만들어요.

## 7. 포트와 Vite 프록시 (CORS 없이 개발하기)

| 포트 | 무엇 | 어디서 정해요 |
|---|---|---|
| **5432** | PostgreSQL (`ownlog-postgres` 컨테이너) | `docker-compose.yml`의 `ports: "5432:5432"` |
| **8080** | Spring Boot (로컬) | Spring 기본값 |
| **5173** | Vite 개발 서버 (브라우저는 여기로 접속) | Vite 기본값 |
| 8301 | e2e "별도 스키마" 방법에서 띄우는 배포 이미지 | `e2e/README.md` |
| 8360 | 운영 서버의 앱 (로컬과 무관) | `deploy.yml`의 `APP_PORT` |

### CORS란?
브라우저는 보안을 위해 **화면을 받은 주소(출처, origin)와 다른 주소**로 API를 부르는 걸 기본으로 막아요. `localhost:5173`과 `localhost:8080`은 포트가 달라서 **다른 출처**예요. 그래서 5173 화면에서 8080 API를 직접 부르면 서버가 따로 허락(CORS 설정)해 주지 않는 한 막혀요.

### 이 프로젝트의 해결: Vite 프록시
`frontend/vite.config.js`
```js
server: {
  // 브라우저는 5173에만 요청하고, Vite가 Spring(8080)으로 대신 전달해요 → CORS가 생기지 않아요
  proxy: {
    '/api': 'http://localhost:8080',
    '/uploads': 'http://localhost:8080',
  },
},
```
```
브라우저 ── GET localhost:5173/api/topics ──▶ Vite ── GET localhost:8080/api/topics ──▶ Spring
   (브라우저 입장에서는 같은 출처 5173이라 CORS 검사 없음)    (서버끼리의 요청은 CORS와 무관)
```
그래서 프론트 코드는 주소를 `'/api'`처럼 **상대 경로**로만 써요 (`src/api/client.js`의 `baseURL: '/api'`). 운영에서도 화면과 API가 같은 주소라 그대로 동작해요. 백엔드에는 CORS 설정이 필요 없어요.

## 8. 처음 설치하기 (한 번만)

```bash
# 0) 저장소 받기
git clone https://github.com/AIP-1/blog-basic-AIGJ_01_007-firstblog.git
cd blog-basic-AIGJ_01_007-firstblog
git switch develop                       # 개발은 develop에서 (main은 운영)

# 1) 환경 변수 파일
cp .env.example .env
openssl rand -base64 48                  # 나온 값을 .env의 JWT_SECRET에 붙여 넣어요
#    .env의 DB_PASSWORD도 아무 값으로 바꿔요 (로컬 전용)

# 2) DB 실행 (Docker Desktop을 먼저 켜요)
docker compose up -d
docker ps                                # ownlog-postgres 가 Up 이면 성공

# 3) 백엔드 (처음엔 Gradle과 의존성을 받느라 몇 분 걸려요)
cd backend
./gradlew bootRun                        # "Started BackendApplication" 이 보이면 성공
#    처음 실행 때 Flyway가 V1~V5를 실행해 테이블을 만들어요

# 4) 프론트엔드 (새 터미널)
cd frontend
npm install
npm run dev                              # http://localhost:5173 접속
```

확인
```bash
curl http://localhost:8080/api/topics    # 토픽 목록 JSON이 오면 백엔드 + DB 정상
```

## 9. 매일 실행하기

```bash
docker compose up -d                     # DB (이미 켜져 있으면 그대로)
cd backend && ./gradlew bootRun          # 터미널 1
cd frontend && npm run dev               # 터미널 2
```
끝낼 때는 각 터미널에서 `Ctrl + C`. DB는 켜 둬도 되고 `docker compose stop`으로 꺼도 돼요.

| 하고 싶은 것 | 명령어 |
|---|---|
| 로컬 DB에 직접 SQL | `docker exec -it ownlog-postgres psql -U ownlog -d ownlog` |
| DB 컨테이너 로그 | `docker logs ownlog-postgres` |
| 프론트 운영 빌드 결과 미리 보기 | `cd frontend && npm run build && npm run preview` |
| 배포와 똑같은 이미지로 실행 | `e2e/README.md`의 "별도 스키마에서 돌리기" 참고 |

`docker compose down`은 컨테이너만 지우고 데이터(볼륨 `ownlog-pgdata`)는 남아요. **`docker compose down -v`는 DB 데이터까지 지워요** (먼저 신중히 생각하기).

## 10. 테스트

### 백엔드: `./gradlew test`
```bash
cd backend && ./gradlew test
# 결과 보고서: backend/build/reports/tests/test/index.html
```
- **Docker가 켜져 있어야 해요.** Testcontainers가 테스트마다 진짜 PostgreSQL 17 컨테이너를 띄워서 테스트해요. (H2 같은 가짜 DB가 아니라 운영과 같은 DB라서, PostgreSQL 전용 SQL도 검증돼요.)
- 처음 실행 때 `postgres:17` 이미지를 받느라 오래 걸릴 수 있어요.
- 특정 테스트만: `./gradlew test --tests 'com.ownlog.image.ImageApiTest'`

### 프론트엔드: 린트와 빌드
```bash
cd frontend
npm run lint        # oxlint. 경고 0이어야 해요 (완료 기준)
npm run build       # 운영 빌드가 되는지. 결과는 frontend/dist/
```

### 화면 점검 (e2e)
```bash
# 백엔드(8080) + 프론트(5173)를 켠 상태에서
node e2e/run-all.mjs                 # 전체
node e2e/run-all.mjs links extra     # 일부만 (check-links, check-extra)
```
- Chrome이 필요해요. 화면을 띄우지 않는 **헤드리스** 방식이라 창이 열리지 않아요.
- 실제로 가입·글쓰기·탈퇴를 해서 **로컬 DB에 테스트 데이터가 남아요.** 시연 데이터만 깨끗이 두고 싶으면 `e2e/README.md`의 **"시연 DB를 건드리지 않고 돌리기"**(배포 이미지를 `e2e` 스키마로 띄워 `BASE=http://localhost:8301 E2E_DB_SCHEMA=e2e`로 실행)를 써요.
- 스크린샷은 `e2e/screenshots/`에 남고 커밋되지 않아요.

GitHub에서는 같은 백엔드 테스트 + 린트 + 빌드가 `ci.yml`(작업 브랜치·develop·PR)과 `deploy.yml`(main)에서 자동으로 돌아요. e2e는 CI에서 돌지 않아요(로컬 전용).

## 12. 자주 나는 문제와 해결

| 증상 | 원인 | 해결 |
|---|---|---|
| `docker compose up` → `port is already allocated` / `address already in use :5432` | 컴퓨터에 PostgreSQL이 따로 설치돼 켜져 있어요 (Homebrew 등) | `lsof -i :5432`로 확인 → 그 DB를 끄거나(`brew services stop postgresql`) |
| `./gradlew bootRun` → `Port 8080 was already in use` | 다른 터미널(또는 IntelliJ)에서 백엔드가 이미 켜져 있어요 | `lsof -i :8080`으로 찾아 종료. worktree 두 곳에서 동시에 켠 경우도 있어요 |
| `docker compose` → `.env 파일에 DB_PASSWORD를 설정해 주세요` | `.env`가 없거나 값이 비었어요 | `cp .env.example .env` 후 값 채우기 |
| `Cannot connect to the Docker daemon` / 테스트에서 `Could not find a valid Docker environment` | Docker Desktop이 꺼져 있어요 | Docker Desktop 실행 후 다시 |
| 백엔드 시작 실패: `password authentication failed for user "ownlog"` | DB 볼륨을 **처음 만들 때의** 비밀번호와 지금 `.env`의 `DB_PASSWORD`가 달라요. PostgreSQL 이미지는 **처음 한 번만** 비밀번호를 설정해요 | `.env`를 처음 값으로 되돌려요. (볼륨을 지우고 다시 만드는 `docker compose down -v`는 **데이터가 전부 지워지니** 먼저 확인) |
| 백엔드 시작 실패: `Could not resolve placeholder 'JWT_SECRET'` | `.env`에 `JWT_SECRET`이 없어요 | `.env`에 추가 |
| 백엔드 시작 실패: JWT 키가 너무 짧다는 오류 (`WeakKeyException`) | 비밀키가 32바이트 미만이에요 | `openssl rand -base64 48`로 다시 만들기 |
| 백엔드 시작 실패: `Validate failed: Migrations have failed validation` / `checksum mismatch` | 이미 실행된 `V*.sql` 파일을 **고쳤어요.** Flyway는 실행한 파일의 지문(체크섬)을 기억해서, 내용이 바뀌면 시작을 막아요 | 고친 파일을 원래대로 되돌리고(`git restore 파일`), 바꿀 내용은 **새 버전 파일**(`V6__...sql`)로 만들어요. 배포된 마이그레이션은 절대 고치지 않아요 (CLAUDE.md 6장) |
| 백엔드 시작 실패: `Schema-validation: missing column ...` | 엔티티에 필드를 추가했는데 마이그레이션이 없어요 (`ddl-auto: validate`) | 새 `V*.sql`로 컬럼 추가 |
| 화면에 "서버에 연결할 수 없어요" / Vite 터미널에 `ECONNREFUSED` | 백엔드(8080)가 꺼져 있어요. 프록시가 넘길 곳이 없어요 | 백엔드 실행 |
| 잘 쓰다가 갑자기 로그인 화면으로 이동 | 로그인 토큰 유효 시간 **2시간**이 지났어요 (`access-token-validity: 2h`). 401을 받으면 자동 로그아웃돼요 | 다시 로그인. 공개 화면은 만료 토큰이어도 튕기지 않게 되어 있어요(트러블슈팅 9번) |
| 로그인이 계속 이상해요 | 브라우저에 예전 토큰이 남았어요 (`localStorage`의 `ownlog.accessToken`) | 개발자 도구 → Application → Local Storage에서 지우기, 또는 로그아웃 |
| `JWT_SECRET`을 바꿨더니 다 로그아웃됐어요 | 예전 키로 서명된 토큰을 새 키로 검증할 수 없어요 | 정상 동작이에요. 다시 로그인 |
| `npm install`·`npm run dev` 오류 (문법 오류, 엔진 버전 경고) | Node 버전이 너무 낮아요 | `node -v`가 v24인지 확인 |
| 이미지가 깨져 보여요 (로컬) | 업로드 폴더는 실행 위치 기준 `./uploads`예요. 루트에서 실행했다가 `backend`에서 실행하면 폴더가 달라져요 | 늘 같은 위치에서 실행하거나 `.env`에 `UPLOAD_DIR` 절대 경로 지정 |
| `node e2e/run-all.mjs` → Chrome을 못 찾아요 | Chrome이 기본 위치에 없어요 | `CHROME_PATH=/경로/chrome node e2e/run-all.mjs` |
| e2e 일부가 실패하고 시연 데이터가 이상해요 | e2e가 로컬 DB에 실제 데이터를 쓰고 지워요 | 시연 DB를 지키려면 별도 스키마 방법 사용 (`e2e/README.md`) |
| IntelliJ에서 Lombok 코드가 빨간 줄 | 어노테이션 처리가 꺼져 있어요 | Settings → Build → Compiler → Annotation Processors → Enable |
| 테스트가 로컬에서는 되는데 CI에서 실패 | `.env`에만 있는 값에 기대고 있어요 | 테스트 설정은 `application-test.yaml`에 두기 |
