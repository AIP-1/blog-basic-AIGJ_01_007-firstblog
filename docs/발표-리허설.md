> OwnLog에서는 글이 **별**이 되고, 글과 글의 연결이 **선**이 돼요. 지금 보시는 건 첫 기록부터 오늘까지 우주가 자라는 모습이에요.

## 5. 예상 질문과 답

| 질문 | 답 |
|---|---|
| 비공개 글이나 봉인된 캡슐이 새지 않나요? | "볼 수 있는가" 판단을 **두 곳**(목록 쿼리의 공개 조건, 엔티티의 `isViewableBy`)에만 두고 모든 기능이 그걸 쓰게 했어요. 목록·검색·태그·링크 대상·우주·사이드바 글 수마다 새는지 확인하는 테스트가 있어요 |
| 테스트는 어떻게 했나요? | 백엔드는 실제 PostgreSQL로 도는 통합 테스트 **169개**, 화면은 헤드리스 Chrome으로 실제로 눌러 보는 점검 **113개**예요. 마감 전에 보안·성능 전체 점검도 해서 인증 우회 같은 문제를 찾아 고쳤어요(`docs/점검-보고서.md`). 둘 다 저장소에 있어서 명령 한 줄로 다시 돌릴 수 있어요 |
| 좋아요를 동시에 누르면요? | 좋아요 수를 DB가 직접 더하고(`+1`), 같은 사람의 중복은 PK로 막아서 동시에 눌러도 정확해요. 동시성 테스트로 확인했어요 |
| 타임캡슐은 스케줄러로 여나요? | 아니요. 공개 시각을 `published_at`에 넣어 두고, 공개 조건에 "그 시각이 지났을 것"을 더했어요. 시각이 지나면 조회에서 저절로 나타나요 |
| 신고는 누가 처리하나요? | 신고 데이터와 중복 신고 방지까지 만들었고, 처리하는 관리자 화면은 2차 계획이에요 (README "앞으로의 계획") |
| 배포는 어떻게 하나요? | main에 푸시하면 GitHub Actions가 테스트 → Docker 이미지 → 서버 전송 → 실행까지 해요. 실행 전에 DB 연결부터 확인해요 |
| 토큰을 localStorage에 두면 위험하지 않나요? | 그래서 마크다운을 그릴 때 sanitize로 스크립트를 모두 막는 걸 전제로 결정했어요. 2차에 Refresh Token과 함께 다시 볼 예정이에요 |
