## 1. 한 줄 소개

**"기록이 시간과 연결로 자라는 블로그"**

다른 블로그는 글이 목록으로 **쌓이기만** 해요. OwnLog는 글이 두 개의 축으로 이어져요.

| 축 | 기능 | 사용자가 느끼는 것 |
|---|---|---|
| ⏳ 시간 | **타임캡슐 글**, **기록 잔디·연대기** | "미래의 나에게 기록을 보내고, 매일의 기록이 쌓이는 게 보여요" |
| 🔗 연결 | **`[[글]]` 링크·백링크**, **기록 그래프** | "내 기록들이 서로 이어진 하나의 우주로 보여요" |

이름 "나만의(Own) 기록(Log)"을 기능으로 보여 주는 것이 목표예요.

## 2. 범위와 순서

단계마다 **문서 → 백엔드 → 테스트 → 화면 → 화면 점검 → 배포**까지 끝내요. 어느 단계에서 멈춰도 발표할 수 있는 완성 상태를 유지해요.

| 단계 | 기능 | 요구사항 ID | 멈췄을 때 발표 메시지 | 목표일 |
|---|---|---|---|---|
| 1 | ⏳ 타임캡슐 글 | TC-01 ~ TC-06 | "기록을 미래로 보내는 블로그" | 10/12 |
| 2 | 🔗 `[[글]]` 링크 + 백링크 | LK-01 ~ LK-05 | "기록이 서로 이어지는 블로그" | 10/13 오전 |
| 3 | 🌌 기록 그래프 | GR-01 ~ GR-04 | **완성형**, 메인 시연 장면 | 10/13 오후 |
| 4 | 🌱 기록 잔디 + 연대기 | AC-01 ~ AC-04 | 마무리 | 10/14 오전 |
| - | 통합 점검, 발표 준비 | - | - | 10/14 오후 |

### 공통 원칙
- **DB는 `V1`을 건드리지 않아요.** 배포 DB에 이미 적용돼 있어서, 단계마다 `V2`, `V3`, ... 마이그레이션 파일을 **추가**만 해요.
- **공개 조건은 지금처럼 한 곳에서만 고쳐요.** JPQL은 `PostCardQueries.PUBLIC_CONDITION`, 엔티티는 `Post.isVisibleToPublic()`이에요. 새 기능도 이 둘을 재사용해서 비공개 글이 새는 일을 막아요.
- **볼 수 없는 글은 지금처럼 404로 숨겨요** (P-06 규칙 유지).
- 새 화면 중 무거운 것(그래프)은 글쓰기 화면처럼 **지연 로딩**해서 메인 첫 로딩 크기를 늘리지 않아요.
- 2차로 미룬 것은 각 절 끝의 "2차"에 적어 둬요.

## 3. 1단계: ⏳ 타임캡슐 글

### 3.1 요구사항

| ID | 내용 |
|---|---|
| TC-01 | 새 글을 발행할 때 **"타임캡슐로 보내기"**를 켜고 **열리는 날짜·시각**(KST, 분 단위)을 정할 수 있어요. 임시저장 글을 발행할 때도 같아요 |
| TC-02 | 열리는 시각은 **지금부터 1분 뒤 ~ 10년 뒤** 사이여야 해요. 1분은 발표 시연용 최소값이에요 |
| TC-03 | 열리기 전(**봉인 상태**)에는 다른 사람에게 **제목, 봉인일, 개봉일, D-day만** 보여요. 본문·요약·썸네일·태그·댓글·좋아요는 숨겨요. 메인·검색·태그·인기·토픽 목록에는 나오지 않아요 |
| TC-04 | **작성자 본인은 봉인 중에도 글을 볼 수 있어요.** 대신 **수정할 수 없어요** (봉인의 의미). 삭제는 할 수 있어요 |
| TC-05 | 개봉 시각이 되면 **자동으로 공개**돼요. 별도 작업(스케줄러) 없이 조회 조건으로 처리해요. 열린 뒤에는 일반 글과 같아요 (수정, 댓글, 좋아요 가능) |
| TC-06 | 블로그 홈에 **"곧 열리는 타임캡슐"**(봉인 중 목록), 메인에 **"최근 열린 타임캡슐"**(최근 7일 개봉)을 보여 줘요. 열린 캡슐 카드와 상세에는 "⏳ 2026.10.12에 봉인된 기록" 배지를 붙여요 |

### 3.2 핵심 설계: `published_at` = 공개되는 시각

새 컬럼은 `sealed_at`(봉인 시각) **하나만** 추가해요. 타임캡슐의 `published_at`에는 **개봉 시각**을 넣어요.

| 컬럼 | 일반 글 | 타임캡슐 |
|---|---|---|
| `sealed_at` | `NULL` | 실제로 쓴(발행 버튼을 누른) 시각 |
| `published_at` | 발행 시각 | **개봉 시각** (미래) |

이렇게 하면 좋은 점:
- **모든 목록에 조건 한 줄이면 끝나요.** `PUBLIC_CONDITION`에 `p.publishedAt <= current_timestamp`만 더하면 메인, 검색, 태그, 토픽, 블로그 목록에서 봉인 글이 한 번에 빠져요.
- **기존 인덱스와 정렬을 그대로 써요.** 모든 목록이 `published_at DESC`로 정렬하니까, 열린 캡슐은 **열린 순간 최신 글 맨 위**에 나타나요. 인기 탭(최근 7일)에서도 새 글로 취급돼요.
- 상세 화면의 "작성일"은 캡슐이면 "봉인 2026.10.12 → 개봉 2026.11.04"로 바꿔 보여 줘요.

### 3.3 DB: `V2__time_capsule.sql`

```sql
ALTER TABLE posts ADD COLUMN sealed_at TIMESTAMPTZ;   -- NULL = 일반 글

-- 봉인 시각은 개봉 시각보다 앞이어야 해요
ALTER TABLE posts ADD CONSTRAINT ck_posts_capsule_order
    CHECK (sealed_at IS NULL OR (published_at IS NOT NULL AND sealed_at < published_at));

-- 블로그 홈 "곧 열리는 타임캡슐"
CREATE INDEX idx_posts_capsule ON posts (blog_id, published_at) WHERE sealed_at IS NOT NULL;
```

### 3.4 서버에서 바꾸는 곳 (영향 범위)

| 위치 | 변경 |
|---|---|
| `PostCardQueries.PUBLIC_CONDITION` | `and p.publishedAt <= current_timestamp` 추가 → 모든 공개 목록에 적용 |
| `Post.isVisibleToPublic()` | `&& !isSealed()` 추가 → 상세, 댓글, 좋아요, 북마크, 신고가 한 번에 막혀요 |
| `Post` 엔티티 | `sealedAt` 필드, `isSealed()`(`sealedAt != null && publishedAt > now`), `publishAsCapsule(openAt)` |
| `CategoryRepository` 네이티브 쿼리 2개 | 사이드바 글 수: `AND published_at <= now()` 추가 (방문자 기준 수에서 봉인 글 제외) |
| `PostQueryService.getDetail` | 방문자가 봉인 글을 열면 404가 아니라 **잠금 응답**을 줘요 (3.5). 조회수는 올리지 않아요 |
| `PostService.update` | 봉인 중이면 `400 TIME_CAPSULE_SEALED` |
| 블로그 글 목록 (주인 본인) | 주인에게는 봉인 글도 🔒 배지와 함께 보여요 |
| `PostCard` (`CARD_FIELDS`) | `sealedAt` 추가 → 열린 캡슐 배지 |

> 경계 시각: 목록은 DB 시계(`current_timestamp`), 상세는 서버 시계(`Instant.now()`)를 써요. 두 시계는 같은 학교 서버 환경이라 차이가 몇 초 이내이고, 그 사이에는 "목록엔 없는데 상세는 열림" 정도의 차이만 생겨서 허용해요.

### 3.7 테스트

**백엔드 통합 테스트** (시간은 SQL로 `published_at`을 과거로 바꿔서 "열림"을 만들어요)
- 1분 미만, 10년 초과, 과거 시각이면 `INVALID_OPEN_AT`
- 봉인 글은 메인·검색·태그·토픽·인기·블로그 목록(방문자)·사이드바 글 수에 없음
- 방문자 상세는 잠금 응답, 본문 `null`, 조회수 그대로
- 봉인 글에 댓글·좋아요·북마크·신고하면 404
- 작성자는 상세에서 본문을 볼 수 있지만, 수정하면 `TIME_CAPSULE_SEALED`, 삭제는 됨
- 개봉 시각이 지나면 모든 목록에 나오고 상세·댓글·좋아요가 동작함, 최신 탭 맨 위
- 임시저장 → 캡슐 발행도 같은 규칙

**화면 점검 (Chrome)**: 캡슐 발행 → 다른 계정으로 잠금 카드 확인 → 개봉 시각을 SQL로 당김 → 카운트다운 끝나고 자동 열림 → 메인 "최근 열린 타임캡슐"

### 3.8 2차
- "나도 열릴 때까지 못 보게 봉인" 옵션, 개봉 알림(이메일), 제목까지 숨기기, 다른 사람에게 보내는 캡슐

## 4. 2단계: 🔗 `[[글]]` 링크 + 백링크

### 4.1 요구사항

| ID | 내용 |
|---|---|
| LK-01 | 본문에서 `[[`를 입력하면 **글 자동완성** 창이 떠요. 내 글이 먼저, 그 아래 다른 사람의 공개 글이 나와요. 고르면 `[[42\|글 제목]]`이 들어가요 |
| LK-02 | 상세 화면에서 `[[42\|글 제목]]`은 **해당 글로 가는 링크**로 보여요. 볼 수 없는 글(비공개, 봉인 중, 삭제됨, 없음)이면 회색 글자 "🔒 볼 수 없는 글"로 보여요 |
| LK-03 | 글 상세 아래에 **"이 글을 언급한 글 (N)"**(백링크)을 보여 줘요. 보는 사람이 볼 수 있는 글만 나와요 |
| LK-04 | 링크 정보는 **발행·수정할 때** 본문에서 다시 계산해요. 임시저장 글의 링크는 기록하지 않아요. 한 글당 최대 50개, 자기 자신 링크는 무시해요 |
| LK-05 | 다른 사람 글로도 링크할 수 있어요. 그 사람의 백링크 목록에 내 글이 보여요 (공개 글일 때만) |

### 4.2 문법을 `[[번호|표시 글자]]`로 정한 이유
- 제목은 **중복될 수 있고 바뀔 수 있어요.** 번호로 연결해야 제목을 바꿔도 링크가 깨지지 않아요.
- 옵시디언의 `[[대상|별칭]]` 형식과 같아서 익숙해요. 사용자는 자동완성만 쓰면 돼서 번호를 외울 필요가 없어요.
- 마크다운 원문에 그대로 남아서, 다른 에디터로 옮겨도 읽을 수 있어요.

### 4.3 DB: `V3__post_links.sql`

```sql
CREATE TABLE post_links (
    source_post_id BIGINT      NOT NULL REFERENCES posts (id),
    target_post_id BIGINT      NOT NULL REFERENCES posts (id),
    created_at     TIMESTAMPTZ NOT NULL,

    PRIMARY KEY (source_post_id, target_post_id),
    CONSTRAINT ck_post_links_not_self CHECK (source_post_id <> target_post_id)
);
CREATE INDEX idx_post_links_target ON post_links (target_post_id);   -- 백링크 조회
```

- 글을 삭제할 때는 지금 댓글·좋아요를 지우는 방식처럼 `post_links`에서 **양쪽 방향 모두** 지워요.
- 글을 수정할 때는 그 글이 출발점인 링크를 지우고 다시 넣어요 (최대 50개라 가벼워요).

### 4.4 서버
- `PostLinkParser`: 정규식 `\[\[(\d{1,18})\|([^\]\n]{1,100})\]\]`로 번호 추출. **코드 블록(```` ``` ````, `` ` ``) 안은 제외**해요.
- `PostLinkService.sync(post)`: 발행·수정 트랜잭션 안에서 호출. 존재하는 글 번호만 저장해요. 권한은 **읽을 때** 검사하니까 저장할 때는 존재 여부만 봐요.
- 공개 여부 검사는 기존 `PUBLIC_CONDITION` / `isViewable()`을 재사용해요.

```json
[ { "id": 51, "title": "Spring Security 적용기", "username": "minsu", "nickname": "민수", "publishedAt": "2026-10-13T10:00:00+09:00" } ]
```

### 4.6 화면

| 화면 | 변경 |
|---|---|
| 글쓰기 | `[[` 입력 시 커서 아래 자동완성 창 (↑↓ Enter, Esc 닫기, 입력할수록 검색). 툴바에 "🔗 글 연결" 버튼도 추가 |
| 글 상세 본문 | `react-markdown`에 **remark 플러그인** 추가: `[[번호\|글자]]` → 내부 링크 / 회색 잠금 글자. 기존 XSS 방지(rehype-sanitize)는 그대로 유지 |
| 글 상세 하단 | 댓글 위에 **"🔗 이 글을 언급한 글 (N)"** 카드 목록 |

### 4.7 테스트
- 발행·수정 시 링크 저장/교체, 코드 블록 안 무시, 자기 자신 무시, 없는 번호 무시, 50개 제한
- 비공개·봉인·다른 블로그 비공개 카테고리 글은 `linkedPosts`에서 `accessible: false`, 제목 없음
- 백링크는 볼 수 있는 글만, 작성자 본인은 자기 비공개 글도 보임
- 글 삭제 시 양방향 링크 정리, 삭제된 대상은 `accessible: false`
- 화면: `[[` 자동완성 → 삽입 → 발행 → 링크 클릭 이동 → 대상 글에 백링크 표시

### 4.8 2차
- 아직 없는 제목으로 링크 → "글 만들기" 유도, 링크 미리보기(마우스 올리면 요약)

## 5. 3단계: 🌌 기록 그래프 ("내 기록 우주")

### 5.1 요구사항

| ID | 내용 |
|---|---|
| GR-01 | 블로그마다 **기록 그래프 화면**(`/@아이디/universe`)이 있어요. 블로그 홈 상단 탭 "글 목록 · 🌌 기록 우주" |
| GR-02 | 글은 **별(점)**, 관계는 **선**이에요. 선은 두 종류: `[[링크]]`(밝은 실선, 방향 화살표), **같은 태그**(흐린 점선, 겹치는 태그가 많을수록 진하게) |
| GR-03 | 별 크기는 **연결 수 + 좋아요 수**, 색은 **토픽**이에요. 봉인된 타임캡슐은 **흐리게 깜빡이는 별**로 보이고, 누르면 잠금 카드로 가요 |
| GR-04 | 끌기·확대·축소가 되고, 별에 마우스를 올리면 제목·태그, 누르면 그 글로 가요. 오른쪽 위 검색창으로 글을 찾으면 그 별로 이동해 강조해요. 휴대폰에서는 손가락으로 끌고 두 손가락으로 확대해요 |

### 5.2 서버: 그래프 데이터를 한 번에 계산

| 번호 | 메서드 | 주소 | 설명 | 권한 |
|---|---|---|---|---|
| 14.1 신규 | GET | `/api/blogs/{username}/graph` | 그 블로그의 별과 선 | 🔓 |

- **별(nodes)**: 보는 사람이 볼 수 있는 그 블로그의 발행 글 (주인은 비공개 포함) + 봉인 캡슐(잠금 별). **최신 300개**까지만 보내요.
- **링크 선**: `post_links` 중 양 끝이 모두 별 목록에 있는 것.
- **태그 선**: `post_tags`를 같은 블로그 안에서 자기 자신과 조인해서, 태그를 1개 이상 공유하는 글 쌍과 공유 개수를 구해요. 별이 많을 때 선이 폭발하지 않도록 **공유 개수가 많은 순으로 최대 1,000개**까지만 보내요.
- 봉인 캡슐은 태그를 숨겨야 하니까 **태그 선 계산에서 빠져요** (링크 선도 없음, 홀로 떠 있는 별).
- 캐시는 일단 두지 않아요. 300개 기준 쿼리 3개라 충분히 빨라요. 측정해서 느리면 그때 추가해요.

```json
{
  "nodes": [
    { "id": 17, "title": "JWT 정리", "topic": "it", "likeCount": 4, "linkCount": 3, "locked": false, "publishedAt": "2026-10-03T..." },
    { "id": 42, "title": "1년 뒤의 나에게", "locked": true, "openAt": "2027-10-12T09:00:00+09:00" }
  ],
  "edges": [
    { "source": 51, "target": 17, "type": "LINK" },
    { "source": 17, "target": 30, "type": "TAG", "weight": 2, "tags": ["Spring", "JWT"] }
  ],
  "truncated": false
}
```

### 5.3 화면
- 라이브러리: **`d3-force`**(물리 배치 계산만 하는 작은 모듈) + **Canvas**로 직접 그려요. 별이 수백 개여도 부드럽고, SVG보다 가벼워요. 끌기·확대는 `d3-zoom`, `d3-drag`.
- **`React.lazy`로 이 화면에서만** 불러와요. 메인 번들 크기는 그대로예요.
- 배경은 어두운 우주색, 별은 은은하게 빛나는 효과. 처음 열 때 별들이 퍼지며 자리를 잡는 애니메이션이 **시연 장면**이에요.
- 글이 없거나 1개면 "첫 기록을 남기면 우주가 시작돼요" 안내.
- 접근성: 그래프 아래에 "목록으로 보기"(연결 수 많은 순 글 목록)를 같이 둬요.

### 5.4 테스트
- 방문자에게 비공개 글·비공개 카테고리 글이 별로 나오지 않고, 주인에게는 나옴
- 봉인 캡슐은 `locked: true`, 제목 외 정보 없음, 태그 선 없음
- 태그 선 공유 개수 정확, 300개·1,000개 제한과 `truncated`
- 화면: 별 개수 = 응답 nodes 수, 별 클릭 시 상세로 이동, 검색 시 강조, 375px에서 가로 스크롤 없음

### 5.5 2차
- 서비스 전체 우주(모든 블로그), 다른 블로그로 나가는 링크를 "다른 은하"로 표시, 시간 슬라이더(날짜를 움직이면 그때까지의 우주)

## 6. 4단계: 🌱 기록 잔디 + 연대기

### 6.1 요구사항

| ID | 내용 |
|---|---|
| AC-01 | 블로그 홈 상단에 **최근 1년 기록 잔디**(GitHub 잔디처럼 하루 한 칸, 글 수만큼 진하게) |
| AC-02 | 잔디 옆에 **"🔥 연속 기록 N일 · 최장 M일 · 올해 K개"**. 연속 기록은 **오늘 또는 어제**까지 하루도 빠짐없이 쓴 날 수예요 (오늘 아직 안 썼어도 어제까지 이어졌으면 유지) |
| AC-03 | 잔디 칸을 누르면 **그날의 기록**(그날 쓴 글 목록)으로 이동해요 |
| AC-04 | 날짜는 **KST 기준**이고, 타임캡슐은 **봉인한 날(쓴 날)**에 칸이 채워져요 ("쓴 기록"이 기준) |

### 6.2 API

| 번호 | 메서드 | 주소 | 설명 | 권한 |
|---|---|---|---|---|
| 14.2 신규 | GET | `/api/blogs/{username}/activity` | 최근 365일 날짜별 글 수 + 연속 기록 | 🔓 |
| 6.4 변경 | GET | `/api/blogs/{username}/posts?date=2026-10-12` | 블로그 글 목록에 날짜 필터 추가 | 🔓 |

- 집계 기준 날짜: `((COALESCE(sealed_at, published_at)) AT TIME ZONE 'Asia/Seoul')::date`
- 보는 사람이 볼 수 있는 글만 세요. 봉인 캡슐은 "봉인했다"는 사실이 이미 공개 목록(12.1)에 있으니 칸에는 포함해요.
- 연속 기록은 서버에서 날짜 목록으로 계산해요 (최대 365개라 가벼워요).

```json
{
  "from": "2025-10-13", "to": "2026-10-12",
  "days": [ { "date": "2026-10-11", "count": 1 }, { "date": "2026-10-12", "count": 2 } ],
  "currentStreak": 2, "longestStreak": 5, "totalThisYear": 31
}
```

### 6.3 화면
- 잔디는 라이브러리 없이 CSS Grid로 그려요 (53주 × 7일). 휴대폰에서는 최근 4개월만 보이고 가로로 넘겨요.
- 칸에 마우스를 올리면 "2026.10.12 · 기록 2개".

### 6.4 테스트
- KST 자정 경계(14:59Z / 15:00Z) 날짜 구분, 연속 기록(오늘 없음+어제 있음 유지, 하루 빠지면 끊김), 비공개 글은 방문자 집계 제외, `date` 필터 목록

## 8. 발표 시연 시나리오 (3분)

1. **우주부터 보여 주기**: 미리 글 15~20개를 `[[링크]]`와 태그로 엮어 둔 블로그의 🌌 기록 우주를 열어요. 별들이 퍼지며 자리를 잡아요. 큰 별을 눌러 글로 들어가요.
2. **연결 만들기**: 새 글을 쓰면서 `[[`를 입력하고 자동완성으로 그 글을 연결한 뒤 발행해요. 대상 글 하단 "이 글을 언급한 글"에 새 글이 나타나요. 우주로 돌아가면 새 별과 선이 생겨 있어요.
3. **타임캡슐**: 발표 시작 전에 "**발표 끝나는 시각**에 열리는 캡슐"을 미리 발행해 둬요. 다른 계정 화면에 잠금 카드와 카운트다운을 띄워 두고, 마지막에 0이 되면서 **화면 앞에서 열리게** 해요.
4. **잔디**: 블로그 홈 잔디와 "🔥 연속 기록 N일"로 마무리해요.

## 9. 위험과 대응

| 위험 | 대응 |
|---|---|
| 시간이 부족함 | 단계마다 배포까지 끝내서, 멈춘 지점이 곧 완성본이에요. 4단계(잔디)는 빠져도 핵심 메시지가 유지돼요 |
| 봉인·비공개 글이 새는 경로 | 공개 조건을 두 곳(`PUBLIC_CONDITION`, `isVisibleToPublic`)에만 두고, 새 API는 반드시 둘 중 하나를 써요. 단계마다 "새는 경로" 전용 테스트를 둬요 |
| 배포 DB 마이그레이션 실패 | `V2`·`V3`는 컬럼·테이블·인덱스 **추가만** 해요. 로컬에서 V1이 적용된 DB에 V2를 올려 보는 테스트 후 배포해요 |
| 그래프가 느림 | 300개·1,000개 제한, Canvas 렌더링, 지연 로딩 |
| `[[ ]]`가 XSS 통로가 됨 | 플러그인은 마크다운 트리(AST)만 바꾸고 HTML 문자열을 만들지 않아요. 기존 rehype-sanitize를 마지막에 그대로 적용해요 |
